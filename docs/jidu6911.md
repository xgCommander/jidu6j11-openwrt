# JioRouter AX6000 JIDU6911: install, upgrade and recovery notes

Notes from running these builds on a JIDU6911. Most of it applies to the
other SKUs too, but only the 6911 was tested; check the UART voltage for
your SKU before connecting anything.

## Identify your SKU

The model number is on the label under the router (`Model No: JIDU6911`).
Flash only the image whose name contains your SKU
(`...-jiorouter_ax6000-jidu6911-squashfs-sysupgrade.bin`). The SKUs differ in
Wi-Fi calibration, antennas and UART voltage.

## Before you start

- **UART is 1.8 V on the 6711, 6811 and 6911.** A 3.3 V USB-serial adapter
  can damage the SoC. Use an adapter with selectable 1.8 V logic (for example
  CH343- or FT232R-based with a 1.8 V jumper) and measure its TX pin with a
  multimeter before connecting it. Never connect the VCC pin.
- Back up every MTD partition before the first flash (`cat /dev/mtdN` over
  SSH, twice, and compare checksums). `0:ART` holds the Wi-Fi calibration and
  MAC addresses, `MFG` the factory data; neither can be regenerated.
- There is no way back to the stock Jio firmware.

## Install from stock firmware

Follow the procedure in the device-support pull request
([openwrt/openwrt#26498](https://github.com/openwrt/openwrt/pull/26498)):
interrupt U-Boot on the serial console, TFTP-boot the initramfs image, then
`sysupgrade` the sysupgrade image from the running initramfs. The first
sysupgrade from the initramfs writes the U-Boot environment
(`bootcmd`, `bootargs`, `mtdids`, `mtdparts`).

**RAM-boot size limit:** this board's U-Boot (2016.01) refuses to boot a FIT
image whose uncompressed kernel would overlap the image itself
("new format image overwritten - must RESET the board"). With the documented
`tftpboot 0x44000000` / `bootm 0x44000000`, the kernel unpacks to `0x41000000`,
so the uncompressed kernel (including the initramfs) must stay below 48 MiB.
The full initramfs images unpack to about 50-80 MiB; a minimal initramfs
(6911 profile only, no LuCI, no extra packages) unpacks to about 42 MiB.

## First boot

No Wi-Fi network is broadcast and the root password is empty. Connect a cable
to a LAN port, open LuCI at http://192.168.1.1, then:

1. set a root password;
2. under **Network > Wireless**, set the **country** where the router is used,
   an SSID and a WPA2/WPA3 key, and enable the networks.

The country sets the legal channels, transmit power and radar (DFS) rules.
Near radar installations, prefer the non-DFS channels (36-48 and 149-165).

## Upgrading

- From one build of this repository to the next (same SKU and board name):
  `sysupgrade` with "keep settings", or LuCI's flash page. Check the image's
  `sha256sums` first; `sysupgrade -T <image>` tests it without flashing.
- From the old combined `jiorouter,ax6000-jidu6j11` images: the board name
  changed, so the image check fails with "Device ... not supported by this
  image". After confirming the SKU on the label, flash once with
  `sysupgrade -F -n` (`-n`: do not keep settings across the board-name change).
  On a 6911 this step was done with `-F` and a minimal settings archive
  instead of `-n`; flash health and the U-Boot environment were unchanged.
- `scripts/validate-image.py <image> <sku>` checks an image before flashing
  (board name, model, calibration variant on both radios, and that the 2.4 GHz
  radio's memory region is enabled).

## Recovery

Without a serial adapter there is no recovery from an image that does not
boot. With one: interrupt U-Boot, log in (reportedly the username is the
last eight characters of the serial number on the label and the password is
stored in the `MFG` partition; not yet confirmed on a 6911), TFTP-boot a
minimal initramfs as above, then `sysupgrade` a known-good image from `/tmp`.

## Hardware notes

- **CPU:** IPQ9554, four Cortex-A73 cores. Each chip has a speed-bin fuse;
  the upstream driver (`qcom-cpufreq-nvmem`) exposes only the frequencies
  Qualcomm allows for that bin. A 6911 here reads bin 1, Qualcomm's "1.5GHz"
  variant (936-1488 MHz).
- **RAM:** 512 MiB, of which about 434 MiB is available to Linux; the rest is
  reserved for the 2.4 GHz Wi-Fi processor (43 MiB), TrustZone, the bootloader
  and the kernel itself.
- **Ethernet:** WAN and LAN1-4 are gigabit (PSGMII). Without the EDMA patch
  0368 (in `tree/`) all receive interrupts are handled by CPU0; with it they
  are spread over the four cores.
- **Wi-Fi:** 2.4 GHz (IPQ9574 integrated) and 5 GHz (QCN9074), both 4x4, up to
  160 MHz on 5 GHz where the country allows it.

## SQM (bufferbloat control)

SQM with CAKE is installed but disabled, with the `wan` interface already
selected. In **Network > SQM QoS**, set download and upload to about 90% of
your plan's speeds, enable it and save. Change the speeds whenever your plan changes.

## Known issues

- Builds whose OpenWrt base contains commit `07d8afca2a` but not the
  `q6_region` fix have no 2.4 GHz radio (`unable to acquire memory-region`).
  The device PR enables it since `727ed7916a1d` (2026-11-26), and the image
  validator rejects affected images.
- Another user reports that USB 3.0 storage degrades 2.4 GHz Wi-Fi on a 6111
  (repo issue #4); not yet checked on the 6911 with a USB 3 device.
